= Changelog

:toc-title: Versions

All notable changes to `aloli-crystal/pdf-tools` are documented
here. The format follows
https://keepachangelog.com/1.1.0/[Keep a Changelog] and
versioning follows https://semver.org/[SemVer]
(3-digit for creations, 4-digit for ports of Ruby gems).

== v0.9.1 — 2026-06-06 — Fix : `tohtml` points to the renamed `pdf2html`

=== Fixed

* **`tohtml` subcommand now forwards to `pdf2html`**, not the old
  `pdftohtml` binary name. `aloli-crystal/pdf2text` v0.6.1 renamed its
  HTML binary `pdftohtml` → `pdf2html` (to avoid the PATH clash with
  poppler's own `pdftohtml`); `alolipdf tohtml` was still resolving the
  old name. Override env var unchanged (`$ALOLIPDF_TOHTML`).

== v0.9.0 — 2026-06-06 — `toppm` and `tocairo` subcommands (native rasterizer)

=== Added

* **`toppm` subcommand** → `pdftoppm` and **`tocairo` subcommand** →
  `pdftocairo` (render PDF pages to PNG/PPM via the native
  `PDF::Raster` rasterizer — no ghostscript). Shell-outs resolved via
  `$ALOLIPDF_TOPPM` / `$ALOLIPDF_TOCAIRO` then `PATH`.
* **The full poppler-utils set is now reachable through `alolipdf`** :
  `info`, `fonts`, `detach`, `attach`, `images`, `tops`, `text`,
  `tohtml`, `toppm`, `tocairo` (external) + `combine`, `validate`,
  `sign`, `verify`, `watermark` (in-process). (Raster rendering is at
  MVP stage — vector only.)

== v0.8.0 — 2026-06-05 — `text` and `tohtml` subcommands (pdf2text, pdftohtml)

=== Added

* **`tohtml` subcommand** → `pdftohtml` (convert a PDF to positioned
  HTML), and **`text` subcommand** → `pdf2text` (extract positioned
  text, `--json` / `--pages`). Both are poppler-named external tools,
  so they stay shell-outs resolved via `$ALOLIPDF_TOHTML` /
  `$ALOLIPDF_TEXT` then `PATH`.
* With these, the whole poppler-utils set ALOLI ports is reachable
  through `alolipdf` : `info`, `fonts`, `detach`, `attach`, `images`,
  `tops`, `text`, `tohtml` (external) plus `combine`, `validate`,
  `sign`, `verify`, `watermark` (in-process).

== v0.7.0 — 2026-06-05 — `tops` subcommand (pdftops)

=== Added

* **`tops` subcommand** → `pdftops` (convert a PDF to PostScript / EPS,
  a ghostscript relay). Like the other poppler-named tools it stays a
  shell-out, resolved via `$ALOLIPDF_TOPS` then `PATH`. `pdftops` lives
  in the `ghostscript` shard (it drives `gs`, not native PostScript
  generation).

== v0.6.0 — 2026-06-05 — `attach` subcommand (pdfattach)

=== Added

* **`attach` subcommand** → `pdfattach` (attach a file to a PDF —
  `/EmbeddedFiles` + `/AF`, Factur-X). Like the other poppler-named
  tools, it stays a shell-out resolved via `$ALOLIPDF_ATTACH` then
  `PATH`. The whole `detach`/`attach`/`images` reading-and-writing
  embedded-file workflow is now reachable through `alolipdf`.

== v0.5.0 — 2026-06-05 — `images` subcommand (pdfimages)

=== Added

* **`images` subcommand** → `pdfimages` (list and extract a PDF's

== v0.4.0 — 2026-06-05 — `detach` subcommand (pdfdetach)

=== Added

* **`detach` subcommand** → `pdfdetach` (list and extract a PDF's

== v0.3.0 — 2026-06-05 — Compiled megabinary (ALOLI tools in-process)

=== Changed

* **`alolipdf` is now a single compiled megabinary**, not a shell-out
  dispatcher. The ALOLI Crystal tools are linked in and invoked
  *in-process* via each tool's `Cli.run(argv) : Int32`:
** `combine` → `CombinePDF::Cli`, `validate` → `PDF::Validate::CLI`,
   `sign`/`verify` → `PDF::Signature::Cli`, `watermark` → `Watermark::Cli`.
* This became possible once the whole suite was levelled onto `pdf` 1.x
  (combine-pdf 1.0.31.40, watermark 0.1.6, validate 0.47, sign 0.12 — all
  on pdf 1.6), and each tool exposed a callable `Cli.run`. No child
  process, **no separate ALOLI binaries to install**.
* **Hybrid by necessity**: poppler's `info` (`pdfinfo`) and `fonts`
  (`pdffonts`) are not ALOLI code, so they stay shell-outs (resolved via
  `$ALOLIPDF_INFO` / `$ALOLIPDF_FONTS` then `PATH`).
* `doctor` now reports the five ALOLI tools as “compilé dans alolipdf
  (in-process)” and only checks the two external tools on `PATH`.

=== Added

* `pdf` shard dependencies on the four ALOLI tools, required by their
  `src/` paths and called in-process (`Tool#runner`).

== v0.2.0 — 2026-06-05

=== Added

* **Two new subcommands** wiring the PDF metadata tools into the
  dispatcher :
** `info` → `pdfinfo` (document metadata : title, dates, pages,
   version…),
** `fonts` → `pdffonts` (font listing : type, encoding, embedded,
   subset).
* Binaries resolved as usual via `$ALOLIPDF_INFO` / `$ALOLIPDF_FONTS`
  then `PATH`; both surface in `alolipdf help` and `alolipdf doctor`.

== v0.1.0 — 2026-06-05

=== Added

* Shard created from
  https://github.com/aloli-crystal/shard-template[aloli-crystal/shard-template].
* **`alolipdf` dispatcher** (`AloliPdf::Dispatcher`) — a unified
  front-end over the ALOLI PDF suite. Each subcommand forwards to the
  matching standalone binary, inheriting stdio and exit code:
** `combine` → `crystal-combine-pdf`, `validate` → `pdf-validate`,
   `sign` → `pdf-sign sign`, `verify` → `pdf-sign verify`,
   `watermark` → `watermark`.
* Built-ins `help [<tool>]`, `version`, and `doctor` (reports which
  underlying tools are installed).
* Per-tool binary resolution: `$ALOLIPDF_<TOOL>` (explicit path) then the
  name on `PATH`. Everything after the subcommand is forwarded verbatim,
  so secrets (e.g. pdf-sign's env-var-name passphrase) never reach argv
  via this layer.
* Design note: shells out rather than linking the shards (their `pdf`
  versions conflict). See `doc/INSTALLER.adoc` for the packaging roadmap.
* `AloliPdf` module with `VERSION` read at compile-time from `shard.yml`.
