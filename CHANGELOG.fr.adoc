== v0.3.0 — 2026-06-05 — Méga-binaire compilé (outils ALOLI in-process)

=== Modifié

* **`alolipdf` est désormais un seul méga-binaire compilé**, plus un
  dispatcher shell-out. Les outils Crystal ALOLI sont liés et appelés
  *en interne* via le `Cli.run(argv) : Int32` de chaque outil :
** `combine` → `CombinePDF::Cli`, `validate` → `PDF::Validate::CLI`,
   `sign`/`verify` → `PDF::Signature::Cli`, `watermark` → `Watermark::Cli`.
* Rendu possible par la mise à niveau de toute la suite sur `pdf` 1.x
  (combine-pdf 1.0.31.40, watermark 0.1.6, validate 0.47, sign 0.12 —
  tous sur pdf 1.6) et l'exposition d'un `Cli.run` appelable par chaque
  outil. Plus de sous-processus, **plus de binaires ALOLI séparés à
  installer**.
* **Hybride par nécessité** : `info` (`pdfinfo`) et `fonts` (`pdffonts`)
  de poppler ne sont pas du code ALOLI ; ils restent en shell-out
  (résolus via `$ALOLIPDF_INFO` / `$ALOLIPDF_FONTS` puis le `PATH`).
* `doctor` indique désormais les cinq outils ALOLI comme « compilé dans
  alolipdf (in-process) » et ne vérifie sur le `PATH` que les deux
  outils externes.

=== Ajouté

* Dépendances sur les quatre outils ALOLI, requis par leurs chemins
  `src/` et appelés en interne (`Tool#runner`).

== v0.2.0 — 2026-06-05

=== Ajouté

* **Deux nouvelles sous-commandes** branchant les outils de
  métadonnées PDF dans le dispatcher :
** `info` → `pdfinfo` (métadonnées du document : titre, dates, pages,
   version…),
** `fonts` → `pdffonts` (liste des fontes : type, encodage, embarquée,
   sous-ensemble).
* Binaires résolus comme d'habitude via `$ALOLIPDF_INFO` /
  `$ALOLIPDF_FONTS` puis le `PATH` ; les deux apparaissent dans
  `alolipdf help` et `alolipdf doctor`.

== v0.1.0 — 2026-06-05

=== Ajouté

* Création du shard à partir du template
  https://github.com/aloli-crystal/shard-template[aloli-crystal/shard-template].
* **Dispatcher `alolipdf`** (`AloliPdf::Dispatcher`) — façade unifiée sur
  la suite PDF ALOLI. Chaque sous-commande relaie au binaire autonome
  correspondant, en héritant de la sortie et du code de retour :
** `combine` → `crystal-combine-pdf`, `validate` → `pdf-validate`,
   `sign` → `pdf-sign sign`, `verify` → `pdf-sign verify`,
   `watermark` → `watermark`.
* Commandes intégrées `help [<outil>]`, `version` et `doctor` (indique
  quels outils sous-jacents sont installés).
* Résolution du binaire par outil : `$ALOLIPDF_<OUTIL>` (chemin explicite)
  puis le nom sur le `PATH`. Tout ce qui suit la sous-commande est relayé
  tel quel, donc les secrets (p. ex. la phrase de passe de pdf-sign passée
  par nom de variable d'env) ne transitent jamais par argv via cette
  couche.
* Choix de conception : shell-out plutôt que liaison des shards (versions
  de `pdf` incompatibles). Cf. `doc/INSTALLER.adoc` pour la feuille de
  route d'empaquetage.
* Module `AloliPdf` avec `VERSION` lue au compile-time depuis `shard.yml`.
