= aloli-crystal/pdf-tools — `alolipdf`
:toc: left
:toc-title: Sommaire

Façade en ligne de commande unifiée `alolipdf` pour la suite d'outils
PDF ALOLI. Un point d'entrée unique et découvrable — `alolipdf <outil> …`
— sur toute la suite, avec une UX cohérente et un `doctor` qui indique ce
qui est installé.

== Principe

`alolipdf` est un seul **méga-binaire compilé**. Les outils Crystal ALOLI
sont liés et appelés **en interne** via le `Cli.run(argv) : Int32` de
chaque outil — aucun sous-processus, aucun binaire séparé à installer.
`info` / `fonts` de poppler ne sont pas du code ALOLI : ils restent en
shell-out (d'où *hybride*).

[cols="1,2,3,1",options="header"]
|===
| Sous-commande | Porté par | Rôle | Mode

| `combine`   | `CombinePDF::Cli`     | fusionner / numéroter / compresser / chiffrer | in-process
| `validate`  | `PDF::Validate::CLI`  | conformité PDF/A-1b·2b·3b et PDF/UA           | in-process
| `sign`      | `PDF::Signature::Cli` | signer (PAdES B-B → B-LTA, TSA, LTV, PKCS#11) | in-process
| `verify`    | `PDF::Signature::Cli` | vérifier les signatures d'un PDF              | in-process
| `watermark` | `Watermark::Cli`      | apposer un filigrane                          | in-process
| `info`      | poppler `pdfinfo`     | métadonnées du document                       | shell-out
| `fonts`     | poppler `pdffonts`    | liste des fontes                              | shell-out
|===

Plus les commandes intégrées `help [<outil>]`, `version` et `doctor`.

Rendu possible par la mise à niveau de toute la suite sur `pdf` 1.x et
l'exposition d'un `Cli.run` appelable par chaque outil — un seul `pdf`
dans le graphe, donc compilation commune.

== Installation

Compiler une fois — tout l'ALOLI est embarqué :

[source,shell]
----
shards build --release
ln -s "$PWD/bin/alolipdf" ~/bin/alolipdf
----

Seuls les outils *externes* `info` / `fonts` nécessitent poppler
(`brew install poppler`, `apt install poppler-utils`…), résolus via
`$ALOLIPDF_INFO` / `$ALOLIPDF_FONTS` ou le `PATH`. `alolipdf doctor`
affiche l'état :

[source,console]
----
$ alolipdf doctor
  ✓ combine    compilé dans alolipdf (in-process)
  ✓ validate   compilé dans alolipdf (in-process)
  ✓ sign       compilé dans alolipdf (in-process)
  ✓ verify     compilé dans alolipdf (in-process)
  ✓ watermark  compilé dans alolipdf (in-process)
  ✓ info       pdfinfo → /opt/homebrew/bin/pdfinfo
  ✓ fonts      pdffonts → /opt/homebrew/bin/pdffonts
----

== Démarrage rapide

[source,shell]
----
export P12_PASS=…                  # la phrase de passe vit dans une var d'env
alolipdf combine merge a.pdf b.pdf -o livret.pdf
alolipdf sign -i livret.pdf -o livret-signe.pdf -c signataire.p12 -p P12_PASS -l b-lt
alolipdf verify livret-signe.pdf -a confiance.pem
alolipdf validate livret-signe.pdf -p pdf-a-2b
----

Tout ce qui suit la sous-commande est transmis **tel quel**, donc la
surface de drapeaux est exactement celle de chaque outil — aucune
duplication, toujours synchronisé. Aucun secret n'est touché : la
convention de pdf-sign (la phrase de passe est le *nom* d'une variable
d'environnement) traverse directement.
