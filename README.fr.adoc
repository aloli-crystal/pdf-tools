= aloli-crystal/pdf-tools — `alolipdf`
:toc: left
:toc-title: Sommaire

Façade en ligne de commande unifiée `alolipdf` pour la suite d'outils
PDF ALOLI. Un point d'entrée unique et découvrable — `alolipdf <outil> …`
— sur toute la suite, avec une UX cohérente et un `doctor` qui indique ce
qui est installé.

== Principe

`alolipdf` est un **fin dispatcher** : chaque sous-commande est relayée au
binaire autonome correspondant, en héritant de sa sortie et de son code
de retour.

[cols="1,3,3",options="header"]
|===
| Sous-commande | Relaie vers | Rôle

| `combine`   | `crystal-combine-pdf` | fusionner / numéroter / compresser / chiffrer
| `validate`  | `pdf-validate`        | conformité PDF/A-1b·2b·3b et PDF/UA
| `sign`      | `pdf-sign sign`       | signer (PAdES B-B → B-LTA, TSA, LTV, PKCS#11)
| `verify`    | `pdf-sign verify`     | vérifier les signatures d'un PDF
| `watermark` | `watermark`           | apposer un filigrane
|===

Plus les commandes intégrées `help [<outil>]`, `version` et `doctor`.

Le choix du **shell-out** (plutôt que lier les shards ensemble) est
délibéré : leurs versions de `pdf` sont incompatibles (combine-pdf en
0.5.x, le validateur/signeur en 1.x), donc un binaire unique compilé
n'est pas possible aujourd'hui. Cette façade apporte l'UX unifiée dès
maintenant.

== Installation

Compiler, puis symlinker le binaire dans le `PATH` :

[source,shell]
----
shards build --release
ln -s "$PWD/bin/alolipdf" ~/bin/alolipdf
----

Chaque outil sous-jacent est résolu via `$ALOLIPDF_<OUTIL>` (chemin
explicite) ou par son nom sur le `PATH`. `alolipdf doctor` affiche la
couverture :

[source,console]
----
$ alolipdf doctor
  ✓ crystal-combine-pdf  →  /Users/vous/bin/crystal-combine-pdf
  ✗ pdf-sign  (absent ; définir $ALOLIPDF_SIGN ou l'installer dans le PATH)
----

== Démarrage rapide

[source,shell]
----
export P12_PASS=…                  # la phrase de passe vit dans une var d'env
alolipdf combine merge a.pdf b.pdf -o livret.pdf
alolipdf sign -i livret.pdf -o livret-signe.pdf -c signataire.p12 -p P12_PASS -l b-lt
alolipdf verify livret-signe.pdf -a confiance.pem
alolipdf validate livret-signe.pdf -p pdf-a-2b
----

Tout ce qui suit la sous-commande est transmis **tel quel**, donc la
surface de drapeaux est exactement celle de chaque outil — aucune
duplication, toujours synchronisé. Aucun secret n'est touché : la
convention de pdf-sign (la phrase de passe est le *nom* d'une variable
d'environnement) traverse directement.
